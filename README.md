# fourmula-clone — information architecture

A pixel-verified clone of fourmula.ai (React 18 + Vite + react-router-dom).
This README covers the **IA layer**. For measured design values — the fluid
root font-size, both theme palettes, the type scale and the full motion
inventory — see [`CLONE_SPEC.md`](CLONE_SPEC.md).

## What's hand-edited vs generated

| file | status |
|---|---|
| `ia.json` | **the only file to hand-edit** — single source of truth |
| `IA.md` | generated by `build.mjs` — do not edit |
| `matrix.csv` | generated by `build.mjs` — do not edit |
| `validate.mjs` / `build.mjs` | copied verbatim from the `ia-builder` skill; generic, no project values baked in |

## Re-running

```bash
node validate.mjs   # hard invariants + informational notes; exits non-zero on failure
node build.mjs      # regenerates IA.md + matrix.csv
```

Edit `ia.json`, then run both. Current state: all hard invariants reconcile,
and every number in every section's `scope` matches its computed route count.

## What the data actually shows

**Reuse is entirely chrome.** 6 of 16 sections are shared across templates and
all six are `SHELL`; every content-bearing section is used by exactly one
template. So there is no latent shared-component work hiding in the content
layer — the shared surface is already extracted into `src/layout/Layout.jsx`,
and the remaining ten sections are correctly page-local.

**The homepage is the build.** It carries 12 of the 16 sections, 7 of them
exclusively, across 1 of 6 routes. The other five routes are chrome plus a
single content block each. Any estimate that treats routes as the unit of
effort will be wrong by roughly an order of magnitude here.

**Chrome is near-universal but not uniform, and the exceptions are real.**
The consent banner, header and awards badge are on all 6 routes; the menu
overlay and footer are on 5 (the not-found template drops both, which is also
why that route has no dot field — the dot field lives inside the footer;
the scroll-progress bar lives in the header and so does appear on the 404); the preloader is on only 2. The `reduced` chrome partition is a
single route.

**One shared shape without a shared component.** `content.legal-document` is
the only section spanning more routes (2) than templates (1), and it is
implemented by two separately authored components — `PrivacyContent.jsx` and
`TermsContent.jsx`. That is deliberate rather than accidental duplication: the
privacy instance carries a cookie data table the terms instance has no
equivalent of. It is the one place in this IA where a future consolidation is
arguable, so it's worth revisiting only if a third legal route appears.

## Two things to know before building against this

**Evidence level is not uniform across templates.** `ia.json` records a
per-template `evidence` field, and it matters:

- `template.home` and `template.not-found` — measured against the live
  original (the homepage matched 1382/1382 elements at 1440px).
- `template.legal` — structure measured, but the body prose is deliberate
  placeholder filler. Any copy budget derived from these routes measures
  filler, not fourmula's real copy.
- `template.app-entry` and `template.auth` — **composed, not measured.** Their
  real targets render client-side only and expose no server-rendered markup,
  so these two pages were built from this project's own design system. Do not
  cite them as fidelity evidence.

**`content.auth-panel`'s form is intentionally inert** — no action, no handler
beyond `preventDefault`, no state, no network. It stands in for a real sign-in
screen and must not be wired up.
